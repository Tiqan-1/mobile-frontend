# Binaa Family — API contract

**Audience:** the Mubadarah backend team. This document stands alone; no app access needed.

**Status:** proposed. The mobile app builds against a local mock implementing exactly this contract, so the two can be developed in parallel and swapped at one boundary.

**Design principle: additive only.** No existing endpoint changes shape or behaviour. Two optional fields are added to `Program`; `Lesson` gains an optional richer field while its existing ones stay for backwards compatibility.

---

## 1. Concept

A parent (**guardian**) authors a study curriculum for their child (**learner**), assigns it, and reviews progress.

The key decision: **a parent-authored curriculum is just a `Program`.** The existing hierarchy already models one exactly —

```
Program   →   Level   →   Task   →   Lesson
curriculum    unit/week   a day      one item (video / pdf / note)
```

So there are no new content entities. A guardian-authored `Program` differs only by `ownerType` and `visibility`. Everything downstream — subscriptions, scheduling, the day view — works unchanged.

---

## 2. Model changes

### `Program` — two new optional fields

| Field | Type | Default | Meaning |
|---|---|---|---|
| `ownerType` | `'org' \| 'guardian'` | `'org'` | Who authored it. Existing programs are `'org'`. |
| `visibility` | `'public' \| 'private'` | `'public'` | `'private'` programs never appear in the public catalogue (`GET /api/students/v3/programs`) and are reachable only by their author and assigned learners. |

Guardian-authored programs are always `ownerType: 'guardian'` + `visibility: 'private'`.

### `Lesson` — new optional `source`

Today a `Lesson` carries `type: 'other' | 'pdf' | 'video'` and a bare `url`. That can't express "this video, but only minutes 3:20–11:05", and can't distinguish a YouTube link from media we host.

Add an optional discriminated union. **Keep `type` and `url` populated** for older clients:

```ts
type LessonSource =
  | { kind: 'hosted';  mediaId: string; playbackUrl: string; posterUrl?: string; durationSec?: number }
  | { kind: 'youtube'; videoId: string; startSec?: number; endSec?: number }
  | { kind: 'pdf';     url: string }
  | { kind: 'link';    url: string };
```

Mapping for backwards compatibility:

| `source.kind` | legacy `type` | legacy `url` |
|---|---|---|
| `hosted` | `video` | `playbackUrl` |
| `youtube` | `video` | `https://youtu.be/{videoId}` |
| `pdf` | `pdf` | `url` |
| `link` | `other` | `url` |

### New entities

**`GuardianLink`** — `{ id, guardianId, learnerId, status: 'pending' | 'active' | 'revoked', createdAt, linkedAt? }`

**`LessonProgress`** — reported by the app, one row per learner per lesson:

```ts
{
  lessonId: string;
  taskId: string;
  levelId: string;
  subscriptionId: string;
  startedAt: string;        // ISO 8601
  finishedAt?: string;
  watchedSec: number;       // cumulative, monotonic
  completedPct: number;     // 0–100
  backgroundedCount: number; // times the app lost focus during this lesson
}
```

`backgroundedCount` is shown to the parent as *information*, not enforcement. Please don't build blocking on it.

## 3. Endpoints

All require the existing `Authorization: bearer <accessToken>`. All `/api/family/*` endpoints act on behalf of the authenticated user in their guardian capacity.

### 3.1 Linking

```http
POST /api/family/invites
→ 201 { code: "7K2M9Q", expiresAt: "2026-08-24T12:00:00Z" }
```
Short-lived (suggest 7 days), single-use, generated by the guardian. 6 characters, unambiguous alphabet (no `0`/`O`/`1`/`I`).

```http
POST /api/family/invites/{code}/accept
→ 200 { link: GuardianLink }
→ 404 unknown or expired code
→ 409 already linked
```
Called by the **learner**. Creates the link in `active` status.

```http
GET    /api/family/learners        → 200 [{ learnerId, name, linkedAt, status }]
DELETE /api/family/learners/{id}   → 204
```
Deletion revokes the link. Assigned curricula stay with the learner — decide with product whether they should be unassigned too; the app treats revocation as "stop reporting progress to that guardian".

### 3.2 Curriculum authoring

```http
POST /api/family/programs
  { name, description?, thumbnail?, start, end }
→ 201 Program                       # ownerType:'guardian', visibility:'private' forced server-side

PUT  /api/family/programs/{id}
  { name?, description?, thumbnail?, start?, end? }
→ 200 Program

POST /api/family/programs/{id}/levels
  { name, start, end }
→ 201 Level

POST /api/family/levels/{id}/tasks
  { date }
→ 201 Task

POST /api/family/tasks/{id}/lessons
  { title, source: LessonSource }
→ 201 Lesson
```

Authorization: 403 unless the caller authored the program. Guardians must not be able to edit `ownerType: 'org'` programs.

```http
POST /api/family/programs/{id}/assign
  { learnerIds: string[] }
→ 200 { subscriptions: Subscription[] }
```
Creates a `Subscription` per learner, same shape as `/api/students/subscriptions/v2/create` produces. 403 if any `learnerId` isn't an active link of the caller.

Deletes (`DELETE` on levels/tasks/lessons) follow the same authorization rule — spec them alongside if product wants full editing.

### 3.3 Media — only for `kind: 'hosted'`

```http
POST /api/family/media/upload-url
  { filename, contentType, sizeBytes }
→ 200 { uploadUrl, mediaId }
```
Direct-to-storage upload URL, so video bytes never transit the API. Recommend **Cloudflare Stream** — per-minute pricing, HLS transcode and signed URLs included, so this endpoint becomes a thin wrapper over their direct-upload API.

```http
GET /api/family/media/{id}/playback
→ 200 { playbackUrl, posterUrl?, durationSec? }
```
`playbackUrl` should be **signed and short-lived** (~1 hour). The app re-fetches on 403 rather than caching it.

Transcoding is async; return `202` with a `status: 'processing'` body until ready, and the app will poll.

### 3.4 Progress

```http
POST /api/progress/sync
  { entries: LessonProgress[] }
→ 200 { syncedAt: "2026-08-17T09:30:00Z" }
```
Called by the **learner's** app. Must be **idempotent** and **last-write-wins per `lessonId`** — the app batches offline and may resend. `watchedSec` is monotonic; take the max rather than overwriting downward.

```http
GET /api/family/learners/{id}/progress?from=2026-08-01&to=2026-08-17
→ 200 {
    learnerId, from, to,
    entries: LessonProgress[],
    summary: { completedLessons, totalLessons, totalWatchedSec, currentStreakDays }
  }
```
Called by the **guardian**. 403 unless an active link exists.

## 4. Notes for implementation

- **Privacy.** A guardian sees progress only for actively-linked learners, and only for the curricula relevant to them. A learner should be able to see who is linked to them.
- **Minors.** Depending on jurisdiction, linking a child account may need recorded consent. Worth a legal check before launch; the app can render whatever consent step you specify.
- **Rate-limit invite acceptance** — a 6-character code is brute-forceable otherwise. Suggest lockout after ~10 failed attempts per account.
- **`GET /api/students/v3/programs` must keep excluding `visibility: 'private'`** or private curricula leak into the public catalogue. This is the one existing endpoint whose behaviour depends on the new fields.

---

## 5. App-side status

The mobile app implements this contract against a local mock backed by WatermelonDB, behind a `FEATURE_FAMILY` flag. When these endpoints land, one module swaps and the flag flips. **No app changes are needed to accommodate reasonable naming adjustments** — tell us what you'd prefer and we'll adapt on our side.
